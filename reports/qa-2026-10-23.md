## 3. What was tested and what passed

### 3.1 Privacy
- 14 tool pages x 2 projects: a JPG with EXIF, a transparent PNG and a WebP processed, ZIP downloaded where offered. Requests recorded at browser-context level (includes the worker). Only same-origin GET/HEAD (HEAD = Next route prefetch). Analytics provider is `none`, so no analytics host exists.
- 12 MP photo and all six converters: same result.
- Security headers present on `/`, a tool page, `/webp-to-jpg`, `/privacy` and the 404 (CSP with `connect-src 'self'`, `form-action 'none'`, `frame-ancestors 'none'`, nosniff).
- No `api/` or upload files in `out/`.
- Output content: EXIF/GPS marker string is absent from outputs (compress and convert); EXIF orientation 6 produces a portrait result (240 x 320).

### 3.2 Tools
- Compress-to-size: 6 pages x (12 MP photo, 2 MP PNG, transparent PNG, signature scan, small JPG, 1000x8000 tall, pure-noise 1200x1200) x 2 projects. All succeeded, output <= target x 1000 bytes (so also <= KiB), file name `{base}-{target}kb.jpg` (`-1mb` for the 1 MB page), downloaded size = `data-output-bytes`, JPEG magic bytes, decodes in the page's own browser at the reported width and height.
- 12 MP photo results (Chromium / WebKit): 20KB -> 19,525 B 731x548 / 19,001 B 602x452; 50KB -> 46,985 B / 47,119 B; 100KB -> 94,930 B / 87,084 B; 200KB -> 191,317 B / 174,307 B; 500KB -> 478,596 B / 487,848 B; 1MB -> 906,178 B / 871,828 B (3507x2630).
- Chip change re-runs; WebP output via More options works in both (Windows WebKit encodes WebP; real Safari not tested).
- Converters: every page with its matching input; MIME by magic bytes, extension, dimensions unchanged; PNG -> JPG and WebP -> JPG give a solid white background (alpha 255, corner white) and the background color picker re-runs with red; WebP/PNG outputs keep alpha; `image-converter` all 3 outputs x JPG/PNG/WebP inputs; GIF first frame with note; BMP accepted.
- Batch of 10 (two with the same name): 10 cards, 10 per-card downloads, ZIP `img-master-compress-image-to-100kb.zip` holds exactly `holiday-1-100kb.jpg` ... `dup-100kb.jpg`, `dup-100kb-2.jpg`, each <= 100,000 B. Batch of 10 to PNG: names and types right.

## 4. What I could not test, and why
- **Real photos**: `e2e/fixtures/real/` is empty. All results use generated images (a photo-like 12 MP JPEG of 2.9 MB, etc.). The real-photo tests are already written and run automatically for any file added there; they skip cleanly now.
- **Real Safari / iOS / Android**: WebKit here is Playwright's Windows build. It has no OffscreenCanvas (uses the main-thread fallback), encodes WebP, skips links in the default Tab order (Safari setting), and has no Share sheet. Real iOS Safari WebP encoding, memory limits for 48 MP, Share button, download behavior and the "Ready, use Share" toast are untested. Keyboard tests on WebKit focus links directly instead of tabbing to them.
- **Throttled benchmarks** (4x CPU) and `reports/benchmarks.json`: section 7 was not part of this task. Timings above are unthrottled, with two tests running in parallel.
- **Lighthouse on the real headers**: impossible locally because of QA-01; scores come from a copy of `out/` with only the COOP line removed. No PageSpeed Insights or Cloudflare preview yet. Host benchmarkIndex was 1000-1150, slower than a typical PSI machine, so absolute scores may differ.
- **Cloudflare behavior**: trailing-slash redirects, `www` redirect, gzip/brotli, and `_headers` parsing by Cloudflare itself are not covered by the local server.
- **Favicon tools**: still draft; only checked that nothing is built or in the sitemap.
- **Analytics-enabled build**: provider is `none`; the privacy test already allows `NEXT_PUBLIC_ANALYTICS_HOST` if set at build time and test time, but that path was not exercised.
- **Screen readers**: no real VoiceOver/TalkBack; only axe plus live-region and role checks.
